# DBHE LCOE calculator

`calculator.html` computes the levelized cost of energy of an array of coaxial deep borehole heat
exchangers with the formula of [Wikipedia](https://en.wikipedia.org/wiki/Levelized_cost_of_electricity),
`LCOE = Σ_{t=1..n} (I_t + M_t + F_t)/(1+r)^t / Σ_{t=α..n} E_t/(1+r)^t`, with yearly intervals. The user sets
I_t, M_t, F_t (on the left, or per year in the table), r, n and α. `E_t` is either a fixed value or the
physical model's heat times the ORC efficiency η, minus the pumping:
`E_t = Σ_months (η Σ_wells ṁ c_p (T_out − T_in) − P_pump) × 730 h` over the 12 months of production year t − α + 1. The heat comes from the physical model of
[GeothermalWells.jl](https://github.com/cwittens/GeothermalWells.jl). For now it is taken from the
100 precomputed cases of its neural-network surrogate (`dbhe_case_library`). The page is static and
runs entirely in the browser, so GitHub Pages serves it like the other pages of the site.

## Files

| File | Role |
|---|---|
| `../calculator.html` | The page |
| `app.js` | Inputs, views and wiring; the only file that touches the DOM |
| `predictor.js` | `LibraryPredictor` (case library), `SurrogatePredictor` (placeholder), the request and prediction contract |
| `economics.js` | `LCOE_DEFAULTS` (literature defaults), `orcEfficiency` (Tester et al. 2006 fit), `heatByYear`, `electricityByYear` and `lcoe` (the formula and its terms) |
| `pumping.js` | Circulation pumping power: Darcy–Weisbach friction (Haaland) in the inner pipe and annulus, water properties; E_t is net of it |
| `layouts.js` | Well positions from layout family, count and spacing; spacing and extent |
| `data/` | Generated by `build_dbhe_assets.py` from `dbhe_case_library` (both in `~/projects/dbhe-lcoe`, not in this repo); do not edit |

Rebuild the data after the library changes:

```
cd ~/projects/dbhe-lcoe
python tools/build_dbhe_assets.py dbhe_case_library ../geothermalarrays.github.io/dbhe/data
```

## Replacing the library with the surrogate

Everything downstream of the predictor uses only the prediction object defined at the top of
`predictor.js`. The surrogate needs to supply the same object:

1. Export the PyTorch model to ONNX (`torch.onnx.export`). Its inputs are the well positions and the
   six parameters `mdot_kg_s, T_inlet_C, k_rock_W_mK, rho_c_rock_J_m3K, gradient_K_m, T_surface_C`.
   These are the arguments of `Borehole` and `HomogenousMaterialProperties` in GeothermalWells.jl that
   the library varies, plus the inlet temperature, gradient and surface temperature.
2. Implement `SurrogatePredictor.predict(request)` with onnxruntime-web. Fill `T_out_C[well][month]`
   on the 240 monthly times in `t_out_years`, and use `heatRateFromOutlet` for `heat_rate_kW`. For the
   rock-cooling view, return a `loadField` that gives an object with the `FieldSlices` methods
   `plan(iYear, iDepth)` and `section(iYear)`, or `async () => null` to hide it.
3. In `app.js` `init()`, construct the `SurrogatePredictor` instead of `LibraryPredictor.load`. Enable
   the "Surrogate model" option in `calculator.html`. With the surrogate the "requested" and "used" inputs
   are the same, so the match card can be hidden when `source.kind === 'surrogate'`.

The surrogate could also run on a server, for example a small Python service. Then
`SurrogatePredictor.predict` posts the request and returns the JSON response, and nothing else
changes.

## Limits that come from the data

- The model gives the heat extracted by the wells; the gross electricity applies the ORC efficiency fit to
  each month's heat at that month's outlet temperature (or a constant η typed by the user), minus the
  circulation pumping power (pumping.js; can be switched off; it neglects both the thermosiphon and the
  surface losses, so it is not a bound).
- With a fixed E_t, n defaults to α − 1 + 30 (30 years of production) and the plant is sized for the
  constant power E_t / 8760 h; the drilling cost of the selected case is kept. The library's outlet temperatures (11–48 °C) are below the range of the ORC efficiency
  fit (plants at 103–166 °C), so the default η is an extrapolation of at most ~2 %. Defaults and their
  sources are in economics.js and the References section of calculator.html.
- The borehole design is fixed: coaxial, 3000 m deep (see `dbhe_case_library/README.md`).
- 20 years of operation at constant flow and inlet temperature, so with E_t from the model n is at most α − 1 + 20.
- A request takes the outputs of the closest case. The match card shows how far each input is from
  that case. Nothing is interpolated.
